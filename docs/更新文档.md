# 知衡更新文档

> **规则：本文档只做线性追加，永不改写历史条目。**
> 每次发布版本在「最新版本」之后追加一节，旧条目保持原样。
> 格式：版本号（tag）→ 日期 → 变更内容 → 验证结果。

---

## 版本规范速查

- 版本格式：`major.minor.patch+build`；**大功能 → major+1，中等功能 → minor+1，小功能/修复 → patch+1，每次发版 build+1**。
- 发版前运行 `bash tool/check_release.sh` 校验；版本号必须与 git tag 一致。
- 完整规则见 docs/约束性文档.md「9. 版本管理」。

## 最新版本

### v1.8.1（2026-09-03）—— 时间线显示修复 · 应用上一次记录 · 输入框明暗对比度

**修复**
- 时间线显示「Instance of PhototherapyExposurePart」：补充摘要生成中 `'$part.name'` 被 Dart 解析为 `${part}.name`（对象 toString），改为 `${part.name}`；历史事件不可变（§44），新增展示层清洗（sanitizeDisplayNotes）过滤已写入的脏文本，不改数据库
- 输入框颜色反转（浅色模式黑底、深色模式白底，文字看不清）：根因是把半透明描边色 `divider` 当填充色用，`withValues(alpha: 0.5)` 覆盖原透明度后亮色变 50% 实黑、暗色变 50% 实白。新增 `fill` / `fillStrong` 次级填充 token，输入框主题、未选中 Chip、内嵌卡片、日期选择按钮、备注气泡全部改用；输入文字/占位符/标签/图标颜色显式指定；补充 error/hover/focus 状态样式（参考 Material 3 filled text field 规范，对比度 ≥ 4.5:1 有测试断言）

**新增功能**
- 时间线「概述 + 点击看细节」：事件卡只展示摘要（照片仅计数，最多 3 行省略），关联任务的事件可点击进入任务详情弹层查看部位/时长/照片完整细节（新增 `getTaskById`）
- 光疗完成弹层「应用上一次记录」：同模板存在历史补充时一键带入上次部位与时长（短周期内治疗部位/时长通常不变），照片不复用；已有输入先确认替换（新增 `lastSupplementedTaskForTemplate`）

**数据变更**：无（schema 保持 v8）

**验证**：flutter analyze 0 issues；flutter test 101/101 通过（原 89 + 新增 12：摘要插值/脏数据清洗/上次记录复用/主题对比度/时间线点击/应用按钮 UI）；输入框明暗渲染经 golden 截图采样确认（亮色 #E9E9ED 浅底深字 / 暗色 #232528 深底浅字）

### v1.8.0（2026-09）—— 光疗任务执行补充 · 模板当天开始 · 正式签名修复

**修复**
- 发布签名（重要）：此前 CI 未配置签名 Secrets，每次 Release 都回退 debug 签名——CI 每次运行的 debug 证书均不同，导致用户覆盖安装报「签名不正确」无法更新。v1.8.0 起 release 构建**强制正式签名**（无 key.properties 直接失败），本地与 CI 共用同一把 key；修复 CI key.properties 路径错误；补充 Android core library desugaring（修复 v1.7.0 Android 打包失败：flutter_local_notifications 依赖）
- 签名凭据二次修正：首轮生成的 keystore 与记录口令不匹配（`KeyStore.load` 校验失败、JKS 摘要不通过），CI Build Android 卡在签名步；随后 base64 复制截断又触发 `base64: invalid input`。已重新生成现行官方 keystore（CN=Zhiheng / alias=zhiheng / RSA2048，SHA-256 `20:42:41:94:…:26`），同步 key.properties、离线备份与 GitHub Secrets（详见 docs/约束性文档.md §10.5）
- Android 桌面应用名 zhiheng → 知衡；iOS 桌面名 Zhiheng → 知衡
- 首页「即将到期」→「未来任务」（语义更准确：未来 7 天待办）

**新增功能**
- 308nm 光疗模板创建计划后**立即从今天开始**首次治疗（原逻辑从明天起找最近模板日，常要等 1–2 天）
- 光疗任务**非计划日勾选提示**：提前完成/补做时提示，确认后按**实际完成日期重排后续光疗任务**（`nextPhototherapyOccurrence`：下次不早于实际完成日后 2 个自然日，保持每周 2～3 次模板节奏）；24h 皮肤反应记录任务也按实际完成时刻生成
- **任务执行补充记录**（可扩展）：勾选 308nm 光疗任务时按部位记录照射时长（分/秒，如 1 分半 = 1 分 30 秒）与患处照片；JSON schema 存储（v8），未来其他疾病/模板可定义新 schema，存储层不感知结构
- **撤销完成保留补充**：撤销仅恢复待办并清理完成事件与派生任务，备注与治疗补充（含照片）保留；任务详情弹层可查看补充并**主动删除**（删除才丢弃，含照片文件清理）

**医学知识库**：录入中国《白癜风诊疗共识（2024 版）》（中华皮肤科杂志 2024;57(12)，DOI 10.35541/cjd.20240260）——308nm 每周 2～3 次、红斑反应驱动的剂量调整、平台期规则；光疗模板依据切换为该共识

**数据变更**：schema v7 → v8（`tasks.supplementJson`、`care_photos.taskId`，向后兼容）

**验证**：flutter analyze 无问题（0 issues）；flutter test 89/89 通过（原 79 + 新增 10）
